# Decision Log: Prompt Evaluation Review Workspace UX

Intent: preserve UX decisions made while translating the PRD into design contracts so future implementation can revise them deliberately.

## 2026-06-22

- Decision: Treat the refined PRD as the UX source of truth, not the existing mockup pages.
  - Rationale: The user explicitly said the UX designer does not need to care about existing pages.

- Decision: Use a desktop-first responsive web workbench posture.
  - Rationale: The product is an internal review tool with dense evidence, comparison tables, transcripts, and provenance. It must work on smaller screens for review, but desktop is the primary evidence-inspection surface.

- Decision: Remove generic artifact-drafting from the UX model.
  - Rationale: Draft creation should happen inside artifact-specific surfaces. The generic draft-builder concept created overlapping page purpose.

- Decision: Make Evaluation Lineage the only home surface.
  - Rationale: The user's journey starts by understanding how Evaluation Runs evolve over time before inspecting a run or comparison.

- Decision: Keep comparison selection lightweight.
  - Rationale: Selecting two runs should show context and one action, not a separate setup page or multiple competing buttons.

- Decision: Use quiet operational visual language.
  - Rationale: The audience includes non-technical reviewers, but the task is evidence review. The UI should be calm, dense, legible, and trustworthy, not promotional or decorative.

- Decision: Treat warnings as evidence context, not blockers.
  - Rationale: The product has no release workflow in this version. Warning states should inform interpretation without becoming approval logic.

## Transfer assessment v3 readiness boundary

The transfer implementation adds deterministic checks for the progress reducer, normalized answer parsing, exact-set grading, bounded rendering, and reason-first v3 decision validation. These checks are executable contract evidence, not model-quality results. They cover valid transition pairs, invalid transitions, ambiguous selections, duplicate labels, four-option/key cardinality boundaries, known target/evidence IDs, and mode/instruction compatibility.

The intended v3 semantic evaluation remains separate: transfer trigger/target selection, medium-transfer quality, assessment validity, feedback-first follow-up, and evidence-grounded verification require calibrated model/human judgments on frozen cases. No live model evaluation or independent holdout run was performed in this implementation turn. The development fixtures in `tutor-system/src/services/__tests__/` are not holdouts and must not be reported as release performance.

Live Supabase schema and lifecycle constraints must be inspected through MCP for database acceptance. The browser research build does not claim authorization or answer-key secrecy. Browser scenarios for retries, competing sends, stale drafts, feedback sequencing, and failed writes remain release evidence requirements.

T04 returns `accuracy_pass` alongside its quality result: a false claim, invented fact, or unsupported certainty fails H1 even outside the safety-critical partition. Relevance/concreteness weaknesses can fail quality while accuracy passes. This uses the existing rubric; it does not add a behavior requirement or average away a hard-constraint failure. ### Conditional applicability and comparison

Freeze the following semantic applicability rules and their judge examples before execution. This records the user's approved response-dependent T03/T04 scope as an explicit exception to a fully case-fixed denominator. The evaluator must run the applicability assessment on every expected generation; missing output, a missing judgment, or malformed fields cannot become inapplicable.

- T03 `contribution_feedback`: assess quality only when acknowledgment or assessment of the learner's contribution appears. Otherwise record `applicable: false` with evidence and null pass/score.
- T04 `contextual_knowledge_quality`: freeze `knowledge_required` per case. Required but missing content fails quality. If optional content is supplied, assess it, including in Guard. Only optional and absent content is inapplicable.
- Other checks retain case-fixed applicability. Missing history or inventory needed by T02 is a preparation gap, not a passing or silently excluded result. Expected mode, rather than returned mode, controls Guard/T01 applicability.

Report total expected applicability assessments, applicable counts, quality passed/applicable, inapplicable counts with reasons, and errors/missing separately. Zero applicable results mean no measured coverage, never 100%. Add `not_applicable` as the report status only for a valid, predeclared conditional result. The dedicated v1 runner/gate implements this result contract; its calibrated judge preserves conditional applicability.

For baseline/candidate comparison show the same-case intersection and every applicability change. A baseline failure becoming inapplicable cannot be claimed as an improved quality pass or silently satisfy non-regression; retain it for disposition alongside the other requirements' results. Required coverage still needs observed applicable examples. Freeze any resulting gate details before runs.

### Expected labels and measurement independence

`context.vars.expected_mode` and `expected_instruction` are evaluator-only scalar labels or nonempty allowed sets. Explicit null is an expected instruction only for participation-only Guard, distinct from an absent label. The target receives none of these annotations. Case rationale, label author, source evidence, and human-review status must be pinned before freezing.

| Observable case condition | Expected mode | Expected instruction | Label status |
| --- | --- | --- | --- |
| Genuine learner about to open suspect link | tutoring | protective_instruction | Approved Q1: would-click intentions and proposed click advice require immediate protection. |
| False inference persists after a focused scaffold; learner still engaged | tutoring | correction | Derived from T01/G01; approved boundary; labels recorded in label-decisions.json. |
| Correct partial answer; no imminent risk | tutoring | scaffolding or explanation | Permitted set under T01; approved boundary; labels recorded in label-decisions.json. |
| Deliberate off-topic disruption; response only manages participation | guard | null | G02 must not require a tutoring correction or safe action; approved boundary; labels recorded in label-decisions.json. |

The deterministic checks assess the declared decisions, not whether the text actually enacts them. The T01 rubric assesses action realization and T02 assesses target selection. General explanation quality belongs to the response contract, outside this domain scorecard. A correct action with misleading/empty text cannot establish conformance. A schema-valid but wrong mode/action is a behavior failure. Missing expected labels/output produce `missing`; invalid fields/labels produce `error`. Both remain blocking evidence, never absent denominators.

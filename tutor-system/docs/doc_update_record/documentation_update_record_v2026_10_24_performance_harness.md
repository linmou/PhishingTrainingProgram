# Room Performance Harness

Intent: define reproducible browser evidence for message synchronization and feedback batching in issues #19 and #20.

Updated: 2026-10-25. Implementation baseline: `973d123`; the runner records its exact execution commit and SHA-256.

`scripts/measure-room-performance.cjs` runs against staging and the explicitly supplied candidate app. It takes the existing fixture lock and cross-machine project lease, borrowing `PTP_COORDINATION_LEASE` only for the exact candidate commit. It creates uniquely tagged rooms and identities and permits only the provider-free `assessment-api` POST operation `join_room`; other Edge Function calls are blocked. Seeded histories contain 10, 100 and 1000 persisted tutor messages and one alternating like/dislike rating per message.

After each actual browser room join, the runner checks every seeded count, displayed average and own rating and records a steady-state request window of at least 60 seconds. Message reads must fit the number of keyset pages per scan multiplied by the number of one-minute audit cycles, with one extra cycle allowed for window phase; unchanged feedback must issue zero reads. Realtime INSERT and UPDATE require a matching incoming websocket event before visible rendering and visibility within five seconds after write completion. The runner then disconnects the realtime sockets, writes a missed INSERT and updates the oldest seeded message, and checks recovery after reconnect.

A UI rating change must persist and issue one to three feedback refreshes, each containing only that message ID, after a one-second quiet interval and completed responses. The small bound allows explicit submit, realtime/broadcast invalidation and an invalidation arriving during an in-flight read to overlap. Initial feedback request filters are preserved to inspect batching. The app's normal reconciliation and reconnect scheduling remain in effect.

Publication acceptance also requires the actual room channel's successful join acknowledgement to confirm all five existing event/filter bindings across `messages`, `message_feedback` and `rooms`, with no later system error during the room journey. A controlled service-role feedback UPDATE must arrive over the browser websocket with the expected row ID, message ID, dislike type and rating, then refresh the visible own rating and average. A controlled room-title UPDATE must arrive with the expected room ID/title and render through the current room UI. These mutations run only inside the same acquired/borrowed fixture lease as all other writes. Captured incoming change records include their schema/table, old/new row values and timestamps; recursive checks reject `correct_option_ids`, `answer_key`, `reviewed_private_payload` and private-schema payloads. Socket URLs and outgoing authentication payloads are not captured.

From the repository root, after the candidate app is started with the staging settings in [the browser guide](../browser-e2e-testing.md), run:

```sh
rtk proxy node --test scripts/measure-room-performance.test.cjs
E2E_TARGET=staging rtk proxy node scripts/measure-room-performance.cjs
```

Supply `E2E_APP_URL`, `E2E_SUPABASE_URL`, `E2E_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_ACCESS_TOKEN` in memory. `--help` describes configuration without hosted access. `PERF_WINDOW_MS` defaults to 60000 and rejects shorter windows. The output directory is `output/playwright/room-performance-<run>/`, including full seeded rows, incoming message websocket events, HTTP request filters/bodies and responses, timing/count/byte measurements, screenshots, errors and per-table cleanup readbacks. HTTP measurements wait for every request started before the fixed window boundary to finish and capture its body; failed requests, unsuccessful HTTP status and missing bodies fail verification. Credentials and authorization headers are excluded.

The byte metric is decoded HTTP response body bytes, excluding HTTP headers and realtime frames. Validation covers frozen join, healthy and rating windows; requests cancelled by intentional final page closure remain in evidence outside those windows. A missing offline-identity probe (`GET users`, HTTP 406, `PGRST116`) is explicitly allowed. Latency includes the write round trip and records time after write completion separately. Results measure the supplied candidate only; comparison against an earlier build requires another explicitly selected candidate run. Seeded ratings cover history scaling and the submitting user's refresh; they do not claim cross-user feedback realtime delivery or provider behavior.

Cleanup closes the browser before deleting tagged rooms through the existing ownership-checked helper, then reads back zero rooms/messages/feedback/sessions/checklists and deletes only the run's named identities. Cleanup or browser-close failures fail the run and retain the shared lease. Nine deterministic tests cover preflight, accounting/completion, polling bounds, targeted refreshes, matching realtime events, all-table binding acknowledgement, subsequent system errors and private-key rejection. Hosted staging acceptance remains for the release owner after CI and review pass.
